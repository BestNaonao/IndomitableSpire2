# 弹药攻击牌炮口表现

## 触发规则

- `TashkentAmmunitionMuzzlePatch` 只处理来源为 `IAmmunitionCard` 且类型为 Attack、实际攻击者为该牌持有者本人、伤害属性为 powered attack 的 `AttackCommand.Execute`。
- 在每个真实攻击段的 `BeforeDamage` 回调触发一次。既支持装填射击等逐次执行攻击的牌，也支持英勇射击的 `WithHitCount`，并遵循最终修改后的攻击段数。群攻一轮只触发一次，不按敌人数倍增。
- 集火、饱和轰炸这类将弹药合并为一次攻击的结算，按实际一次攻击表现，不从消耗弹药数量推测额外伤害段。纯装填、技能牌、非弹药攻击、无效目标、零攻击段、非攻击追加伤害均不额外触发。
- 原有 `BeforeDamage` 回调完整保留：若原回调异步，则仅等待其原有任务后再播放；若原回调失败，不假造开炮。重复执行同一 AttackCommand 不重复叠加本补丁的包装。
- 没有额外动画等待，不修改伤害、弹药消耗、目标、攻击次数或原角色动作。没有新增玩法 RNG、网络消息或每帧网络同步。

## 视觉

- 炮口按角色命中中心和 Bounds 宽度放在身前，跟随 Body 的实际左右朝向；各皮肤与静态模型通用。本地与远端角色各有独立节点。
- 暖白短闪约 0.06 秒，短喷焰约 0.12 秒，少量烟尘约 0.56 秒散去。闪光与喷焰为加法混合；烟雾使用普通透明混合，无黑色矩形。
- 整体视觉倍率为 2：短闪／喷焰的尺寸与相对偏移、余烟尺寸／散布／漂移范围均为初版的两倍。炮口锚点、透明度、持续时间、队列节奏和粒子数量不变。
- 高速／同帧多段攻击采用最小 0.075 秒的视觉发射间隔，六段可区分为六次闪光。队列仅用于表现，伤害无需等待；极端连击最多保留 12 个待播闪光，超过的视觉请求合并，实际攻击次数完全不受影响。
- 每名角色只保留一个控制器、两张闪光／喷焰 sprite 和八张复用烟尘 sprite；不逐发创建粒子发射器。烟尘保留世界坐标，不会因角色随后位移而拖着走。
- 图层在 HealthBar／意图 UI 后方；所有节点不拦截输入。最后一次闪光约 0.65 秒后自动释放，死亡、战斗结束立即清掉余烟与未播队列，不延迟奖励。

## 验证边界

完整模组针对当前游戏程序集编译通过；当前与 `_107` 官方源码均确认了同名 Execute 入口与 `_beforeDamage` 回调位置。

隔离 Godot 工程链接生产节点和补丁，使用真实 Harmony PatchAll、实际导入纹理和渲染，模拟官方每段攻击／伤害边界。Compatibility 与 Mobile 各通过 30 项检查，包括：三段／六段闪光、群攻计数、原回调与原伤害计数不变、同一命令重复执行、异步及失败回调、两种朝向、闪光与喷焰分段消退、烟尘回收、排除非弹药／技能／追加伤害／零段／宠物替代攻击、TestMode、100 段预算限制、死亡、两名角色独立队列和战斗结束解绑。

这不等同于完整游戏联机实战或每个正式版／Beta 版本的实际加载验证。测试工程与预览：`D:/GitClone/.codex-build/tashkent-muzzle-qa`。

两倍尺寸调整后，两种渲染路径各通过 33 项检查，新增验证左右两倍缩放、短闪精确为 190×130、余烟在相同时间点精确为原尺寸两倍。
