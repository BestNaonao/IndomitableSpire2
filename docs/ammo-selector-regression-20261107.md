# 弹药选择界面检查（2026-11-07）

## 用户报文的原因与修复

1. 本地化错误并非滑条本身未填写数值。战斗奖励界面的 `LoadPreviewStrings` 读取了整份 `gameplay_ui.json`，随后对每个键调用不带变量的 `GetFormattedText()`；新增的 `TASHKENTSPIRE2-SHELL_SELECTOR.available` 包含 `{amount}`，因此奖励界面初始化时报错。现在只读取 `TASHKENTSPIRE2-BATTLE_REWARDS.` 命名空间，不触碰其他界面文案。滑条仍读取原文并自行替换数量。
2. `card_frame_sdf.exr` 的 `Asset not cached` 是同步回退加载警告，不是文件缺失。BaseLib 的奖励高亮使用这张原版纹理；现在将其加入塔什干额外预加载列表，即使关闭自定义奖励界面也会预加载。未修改 BaseLib、原版资源或全局日志等级。
3. 同时为弹药选择场景和头像补充资源预加载声明，减少首次打开时的加载工作。

## 额外发现并修复的问题

- 窗口被设置等其他界面覆盖时，原先没有停用确认和查看战场按钮。现在隐藏时停用按钮及快捷键，恢复时重新启用；只有当前顶层、可操作且不在查看战场状态的窗口能够确认。
- 外部移除或清空覆盖窗口栈时，原先可能只移除列表而不释放节点，选择任务依赖退出节点才能完成。现在关闭回调主动返回 0 并释放节点，退出节点仍保留兜底，避免选择等待悬挂。
- 连续确认只允许完成一次选择、移除一次窗口；关闭或覆盖时恢复查看战场状态。
- 界面打开后切换语言再返回，顶部提示原先保留旧语言。现在重新生成带实际弹药数和上限的提示，同时刷新滑条本地化。

本轮未修改按钮位置、大小、悬停缩放、输入提示样式、滑条背景或其他布局。没有改动弹药消耗、集火结算或联机消息格式。

## 性能、同步与验证边界

滑条只在真实档位变化时更新预览，显示层没有逐帧轮询。拖动不发送网络消息；确认后沿用原有 `PlayerChoiceSynchronizer`，只同步一个最终整数。远端与回放分支不打开本地选择界面。测试确认重复点击不会重复发送，预览切换也不会重新创建游戏模型中的七张选项牌。

交互测试使用实际 Godot HSlider；按钮测试包含原版按钮源码及原生动画帧。选择流程和协议测试使用模型、窗口栈及网络同步测试替身，不等于实机多人对局验证。仍建议在正式游戏中检查一局鼠标/手柄切换，并由两名玩家各操作一次选择、查看战场和确认。资源及编译产物均在隔离测试目录，未自动部署至 Steam 游戏目录。
