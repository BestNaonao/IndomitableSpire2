# 蓄力打击 / 致命一击近身演出

两张牌通过 `NCloseStrikeVfx.Attach` 接入同一套纯视觉近身控制器。

- 蓄力打击：四套皮肤各自新增 `tashkent_charge_crouch` 骨骼片段，0.2 秒内骨盆下降 17／18 个骨骼单位、屈膝并轻微前倾，随后保持至 0.68 秒，突进仍为 0.16 秒；快速模式蓄势 0.34 秒、突进 0.08 秒。不再缩放或旋转整个 Body，蓄势时也不整体平移，让双脚保持原地、头身比例不变。
- 致命一击：取消蓄势，普通速度约 0.08 秒、快速模式约 0.04 秒贴近命中。命中短停 0.1 秒后，以 0.36～0.64 秒的短弧线跳回原位（原 0.18～0.32 秒的两倍），跳跃高度仍在 35～80 世界单位内变化。回程的 Spine track entry 单独半速，不改变后续攻击或待机。
- 沿用角色原有 `Attack` → Spine `attack` 基础轨道；四套皮肤都有 0.2 秒的 `action` 关键点。蓄势在专用 track 1 叠加无事件的下蹲片段，突进时平滑退出，实际伤害回调清掉附加轨道并将原攻击对齐到命中帧。不改写原动作或贴图；`.skel` 只追加约 3 KB 的新骨骼时间轴。
- 保留敌人中心的原版 `vfx_heavy_blunt`。蓄力打击在敌人旁停留 0.23 秒覆盖其预备阶段；致命一击更早跳开。回位只在视觉帧中进行，不 await、不冻结全局时间。
- 蓄力打击保持修改前代码中的 750 世界单位/秒匀速撤回；致命一击改用上述快速跳回。两者都不影响普通距离后撤，不随卡牌或快速模式压缩回程时间。回程播放现有 `move_left`，自然到达后才恢复待机。
- 从初始 `Attack` 开始后的第一个视觉帧监听新动作：攻击、受击、施法、死亡、胜利或另一段移动均可立即接管，包括重新播放同名动作。被打断时立即清除旧偏移和自己持有的下蹲轨道，不覆盖新动作；轨道已被其他动画占用则不抢占，同名附加动作重播也交还所有权。清理与退订同步完成，没有延迟待机回调。

## 结算与兼容

保持原有伤害、伤害结果统计、蓄力打击的活力，以及致命一击的标记 / 保留 / 消耗。通过官方 `WithAttackerAnim("Attack", delay)` 分别设置 0.84 秒和 0.08 秒的等待，保留攻击音效，并让蓄力伤害随延长的蓄势发生，致命命中节奏不变。`CreatureCmd.TriggerAnim` 的 Fast 等待上限是 0.25 秒，因此只对蓄力附加 `AfterAttackerAnim` → `Cmd.CustomScaledWait(0.17, 0)`，补足快速模式的 0.42 秒；普通模式不多加等待，即时模式仍跳过。全部使用官方命令时钟，不等待本地视觉节点或新增异步计时器。非塔什干角色使用这两张牌时不改原来的等待。

仅移动角色 `Body` 的附加偏移，不修改 `NCreature`、血条、意图、碰撞范围、距离层数、怪物位置、RNG 或网络消息。各客户端从相同攻击结算回调启动本地演出，无本机玩家过滤。没有 Spine 时仍可做模型位移；其他角色获得这两张牌时保持自己的默认演出。

连续重播会先清除旧偏移。目标在命中前失效、攻击被动作打断、攻击者死亡、模型切换、场景退出、战斗结束都会回收；命中后敌人死亡仍可正常回位。未走到伤害回调时有 1.25 秒的视觉保险回收。清除时只撤销本控制器施加的位移与附加动作，不修改原始缩放／旋转或其他布局改动，保留左右镜像。
